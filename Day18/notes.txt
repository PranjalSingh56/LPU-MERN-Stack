1) VIRTUAL DOM
------------------------------
Definition:
Virtual DOM is a lightweight JavaScript representation (copy) of the real DOM.
It exists only in memory and is used by frameworks like React to calculate UI
changes efficiently before updating the actual browser DOM.

Key Points:
- It is NOT the real webpage.
- It is a tree-like JavaScript object.
- Created after every render/state change.
- Helps reduce direct manipulation of the real DOM.

Why Virtual DOM?
- Real DOM updates are slow and expensive.
- Virtual DOM allows React to plan changes first.
- Only necessary updates are applied to the real DOM.

Simple Line:
Virtual DOM = Fast, invisible blueprint of the UI.


2) DIFFING
------------------------------
Definition:
Diffing is the process of comparing the OLD Virtual DOM with the NEW Virtual DOM
to find what has changed.

Purpose:
- Detect added elements.
- Detect removed elements.
- Detect updated properties or text.

Important Rules Used by React:
- Different element type => Replace entire subtree.
- Same element type => Update only changed attributes.
- Lists use "key" to track identity.

What Diffing Does NOT Do:
- It does not directly update the real DOM.
- It only calculates differences.

Simple Line:
Diffing = Finding differences between two Virtual DOM trees.


3) RECONCILIATION
------------------------------
Definition:
Reconciliation is the complete process React uses to update the UI after state
changes. It includes diffing, deciding what to update, and applying minimal
changes to the real DOM.

Steps Inside Reconciliation:
1. State or props change.
2. New Virtual DOM is created.
3. Diffing compares old vs new trees.
4. React decides which components update.
5. Real DOM is updated minimally.

Goal:
- Keep UI synced with latest state.
- Avoid unnecessary DOM operations.

Simple Line:
Reconciliation = Updating the real UI efficiently using diffing results.


4) RELATION BETWEEN ALL THREE
------------------------------
Flow Order:

State Change
    ↓
New Virtual DOM Created
    ↓
Diffing (compare old vs new)
    ↓
Reconciliation (apply updates)
    ↓
Real DOM Updated


5) QUICK MEMORY SUMMARY
------------------------------
Virtual DOM:
    JavaScript copy of real DOM.

Diffing:
    Process of finding what changed.

Reconciliation:
    Full update cycle that applies changes to real DOM.


==============================
JSX (JavaScript XML) — NOTES
React Core Concept
==============================


1) WHAT IS JSX?
------------------------------
Definition:
JSX (JavaScript XML) is a syntax extension used in React that allows developers
to write HTML-like code inside JavaScript. It makes UI code easier to read and
write.

Important:
- JSX is NOT HTML.
- Browsers do NOT understand JSX directly.
- JSX gets converted into normal JavaScript using tools like Babel.

Simple Line:
JSX = HTML-like syntax written inside JavaScript.


2) HOW JSX WORKS INTERNALLY
------------------------------
JSX Code:
    <h1>Hello</h1>

Converted JavaScript:
    React.createElement("h1", null, "Hello")

Process Flow:
Write JSX
    ↓
Babel compiles JSX
    ↓
Normal JavaScript generated
    ↓
React creates Virtual DOM


3) WHY JSX IS USED
------------------------------
- Makes UI structure easy to understand.
- Cleaner than writing React.createElement manually.
- Improves readability and maintainability.
- Keeps UI and logic in one place.


4) BASIC JSX RULES
------------------------------

Rule 1: Only ONE parent element must be returned.
Example:
    return (
        <div>
            <h1>Hello</h1>
            <p>World</p>
        </div>
    );

Rule 2: Use className instead of class.
    <div className="box"></div>

Rule 3: Use {} to write JavaScript inside JSX.
    const name = "Raj";
    <h1>Hello {name}</h1>

Rule 4: Self-closing tags must be closed.
    <img src="image.png" />

Rule 5: Attributes use camelCase.
    onClick
    backgroundColor


5) JSX VS HTML (KEY DIFFERENCES)
------------------------------
HTML uses:
    class
    onclick

JSX uses:
    className
    onClick

JSX allows JavaScript expressions using {}.


6) RELATION WITH VIRTUAL DOM
------------------------------
JSX does NOT directly update the real DOM.

Flow:
JSX → JavaScript Object → Virtual DOM → Diffing → Reconciliation → Real DOM


7) QUICK MEMORY SUMMARY
------------------------------
JSX:
    HTML-like syntax inside JavaScript.

Purpose:
    Easier UI writing.

Reality:
    JSX compiles into React.createElement() calls.

REACT COUNTER + useState — SHORT NOTES
==============================


1) COUNTER CONCEPT
------------------------------
Counter is a simple React component that increases or decreases a number using state.

Main Idea:
State change → Component re-render → UI update automatically.


2) useState (HOOK)
------------------------------
Definition:
useState is a React Hook used to store and manage data inside functional components.

Syntax:
const [state, setState] = useState(initialValue);

Example:
const [count, setCount] = useState(0);

count     → current value
setCount  → function to update value
0         → starting value


3) BASIC COUNTER CODE STRUCTURE
------------------------------
import { useState } from "react";

function Counter() {
    const [count, setCount] = useState(0);
    return (
        <div>
            <h1>{count}</h1>
            <button onClick={() => setCount(count + 1)}>+</button>
            <button onClick={() => setCount(count - 1)}>-</button>
            <button onClick={() => setCount(0)}>Reset</button>
        </div>
    );
}


4) HOW COUNTER WORKS (FLOW)
------------------------------
User clicks button
    ↓
setCount() runs
    ↓
State updates
    ↓
New Virtual DOM created
    ↓
Diffing + Reconciliation
    ↓
Real DOM updates


5) IMPORTANT RULES
------------------------------
- Never change state directly.
    count = 5  ❌
    setCount(5) ✅

- useState must be used at top level of component.
- State update triggers re-render.


6) QUICK MEMORY SUMMARY
------------------------------
Counter = State + JSX + Button Events.

useState:
Stores value and updates UI automatically.

==============================
useEffect — SHORT NOTES (React Hook)
==============================


1) WHAT IS useEffect?
------------------------------
Definition:
useEffect is a React Hook used to handle side effects inside functional components.
It runs code AFTER the component renders.

Side Effects Examples:
- API calls
- Timers
- Event listeners
- Console logs
- Local storage access

Simple Line:
useEffect = Code that runs after render.


2) BASIC SYNTAX
------------------------------
useEffect(() => {
    // side effect code
}, [dependencies]);


3) DEPENDENCY ARRAY CASES
------------------------------

Case 1: Empty Array []
Runs only once after first render (component mount).

    useEffect(() => {
        console.log("Run once");
    }, []);


Case 2: With Dependencies
Runs when specific value changes.

    useEffect(() => {
        console.log("Count changed");
    }, [count]);


Case 3: No Dependency Array
Runs after every render.

    useEffect(() => {
        console.log("Runs always");
    });


4) HOW useEffect WORKS (FLOW)
------------------------------
Component Render
        ↓
UI updated
        ↓
useEffect executes


5) IMPORTANT RULES
------------------------------
- Always place useEffect at top level of component.
- Avoid unnecessary state updates inside effect.
- Dependency array controls when effect runs.


6) QUICK MEMORY SUMMARY
------------------------------
useEffect:
Handles side effects after render.

[]        → run once
[value]   → run on change
(no array)→ run every 


1) CDN (Content Delivery Network)
------------------------------
Definition:
it is a server network that deliver files through the browser using URL
 
A CDN is a network of servers used to deliver files like React, CSS, images,
and scripts quickly from the nearest location to the user.

Purpose:
- Faster loading
- Reduced server load
- Easy setup without installation

Example:
<script src="https://unpkg.com/react@18/umd/react.development.js"></script>

Simple Line:
CDN = Load libraries directly from the internet.


2) BABEL
------------------------------
Definition:
Babel is a JavaScript compiler (transpiler) that converts modern JavaScript
and JSX into browser-friendly JavaScript.

Why Needed:
- Browsers do not understand JSX.
- Older browsers may not support modern JS.

Example:
JSX:
    <h1>Hello</h1>

Converted:
    React.createElement("h1", null, "Hello")

Simple Line:
Babel = Converts new JS/JSX into normal(coded) JavaScript.


3) PARCEL
------------------------------
Definition:
a JavaScript bundle + built tools
it is a software that reads your local project files, compies JSX, ES6, CSS and images
it bundles everything into optimised JS

Parcel is a zero-configuration web bundler used to build and run web apps.
Main Features:
- Bundles files automatically
- Fast development server
- Hot reload
- Handles images, CSS, JS together

Command:
npx parcel index.html

Simple Line:
Parcel = Tool that builds and runs your project automatically.




4) BUNDLE
------------------------------
BUNDLE = one combined JavaScript files (JavaScript, CSS, assets, images and components)
Definition:
A bundle is a single optimized file created by combining multiple files
(JavaScript, CSS, assets) into one.

Purpose:
- Faster website loading
- Reduced HTTP requests
- Optimized performance

Example:
Many JS files → one main.js bundle

Simple Line:
Bundle = Combined optimized output file.


5) RELATION BETWEEN ALL
------------------------------
CDN:
    Loads libraries from internet.

Babel:
    Converts JSX/modern JS.

Parcel:
    Builds and bundles project.

Bundle:
    Final optimized output file.

====================================
REACT LIFECYCLE — SHORT NOTES
====================================

1) componentDidMount()
------------------------------
Runs after component mounts (first render).
Used for:
- API calls
- Timers
- Event listeners

Memory Line:
First time screen pe aane ke baad.


2) Re-rendering
------------------------------
Component runs again when:
- State changes
- Props change
- Parent re-renders

React updates only changed DOM parts.


3) componentDidUpdate()
------------------------------
Runs after component updates (re-render).
Used for:
- Side effects after update
- Comparing old vs new data


4) componentWillUnmount()
------------------------------
Runs before component is removed.
Used for:
- Cleanup
- Stop timers
- Remove listeners


====================================
Flow:
Mount → Update → Unmount
====================================



====================================
ONE-WAY DATA BINDING — TECH DEFINITION
====================================
One-way data binding is a data flow model in which data moves
in a single direction, typically from the component state or
parent component to the UI (view). Changes in data update the UI,
but UI changes do not directly modify the source data.

Key Idea:
State/Props → View (Unidirectional Flow)

Used In:
React (default behavior)


====================================
TWO-WAY DATA BINDING — TECH DEFINITION
====================================
Two-way data binding is a data synchronization model where
changes in the data automatically update the UI, and user
interactions in the UI automatically update the underlying data.

Key Idea:
Data ↔ View (Bidirectional Flow)

Used In:
Angular, Vue (with specific directives)


====================================
CORE DIFFERENCE
====================================
One-Way  : Data flows in one direction only.
Two-Way  : Data and UI stay automatically synchronized both ways.
====================================
